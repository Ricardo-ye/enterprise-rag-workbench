# 示例退款政策（仅用于系统验证）

> 该文档是面向 RAG 检索与回归测试的**合成演示数据**，不构成任何企业、平台或商品的真实退款承诺。真实业务必须以已审批的合同、产品协议、地区法律与正式政策为准。

## 适用范围

本示例覆盖三类常见的消费服务咨询：用户主动取消尚未履约的订单、发生重复扣款、以及服务已部分使用后的退款咨询。它的目的，是让系统能区分“退款政策”这一业务问题与仅包含“FAQ”“政策”等泛词的技术文档。

## 示例退款政策

本示例退款政策规定：未使用且未履约的订单可以申请退款；系统在核验订单、支付状态和服务使用记录后处理申请，不承诺固定金额或到账时效。

对于**未使用且未履约**的订单，用户可以提交退款申请。系统应核验订单状态、支付状态、服务使用记录与必要的身份信息；核验通过后进入人工或自动化处理队列。

对于**重复扣款**，应先核验支付流水与订单号，确认属于同一笔订单的重复支付后再按原支付路径处理。对于**已部分使用的服务**，系统不得自动承诺退款比例、到账时间或金额，应转交已授权的业务人员依据正式规则处理。

## 处理原则

1. 先说明这是示例政策，不能替代真实企业规定。
2. 不对到账时间、退款金额或审核结果作保证性承诺。
3. 证据不足、订单状态不明或涉及争议时，建议用户提供订单号并转人工核验。
4. 若文档与已审核 FAQ 冲突，以最新审批版本的 FAQ 或正式政策文档为准。

## 回归问题样例

- 退款政策有哪些核心规则？
- 我还没使用服务，可以申请退款吗？
- 为什么同一笔订单扣了两次款？
- 服务用了一部分还能退吗？

上述问题仅用于验证检索相关性、拒答行为和引用链路；答案不得被用于实际交易决策。
